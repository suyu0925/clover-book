一、用户与权限
家庭有多少成员需要使用？是否需要多用户登录？
家庭有多个成员需要使用，所以需要支持多用户登录，并且允许多个用户同时一起编辑和查看同一个账本。

是否需要权限区分？（比如管理员可以管理账户/分类，普通成员只能记账和查看）
需要区分账本的管理权限，但账本里的分类和编辑、查看权限不需要区分。比如A创建了一个账本，并分享给了B。那么B不可以删除账本，但可以修改分类、记账和查看等。

是否需要记录"谁记的这笔账"？
要记录。

二、账户与记账模型
需要支持哪些账户类型？（银行卡、信用卡、现金、支付宝/微信、投资账户等）
常规的账户类型都需要支持。

是否需要多币种支持？
不需要支持多币种，因为汇率不好设计。

交易类型有哪些？（支出、收入、转账、报销、借入/借出？）
常规的交易类型都有。

是否需要支持定期/周期性交易？（如每月房租、工资）
需要，比如分期付款、房贷、房租等。

三、分类与标签
分类体系是怎样的？（一级分类 + 二级分类？还是自由标签？）
一二级分类和自由标签都要有。

是否需要预设一套常用分类？（餐饮、交通、购物、医疗等）
要

四、预算与统计
是否需要预算管理功能？（按月/按分类设定预算，超支提醒）
需要，你来设计。

需要哪些报表/统计？（月度收支、分类占比、趋势图、家庭成员消费对比等）
常用的都要，你来设计。

五、Beancount 相关
Beancount 文件组织方式？（单文件？还是按年/月拆分多文件？）
采用单文件。

是否需要支持直接编辑 Beancount 源文件的功能？（高级用户可能需要）
可以支持。

数据库缓存选用什么？（SQLite 轻量方便？还是 PostgreSQL？）
使用postgresql。

六、部署与其他
部署目标是什么？（自家 NAS？云服务器？Docker？）
需要支持docker部署。

是否需要数据导入功能？（从银行账单 CSV、支付宝/微信账单导入）
特别需要有数据导入功能。设计一个支持的导入格式，尽量通用一点。后续要从随手记里把数据导出来。

是否需要附件功能？（拍照上传小票/发票）
特别需要，如果附件可预览要在前端支持预览。


补充确认：
账本概念：一个用户可以创建多个账本吗？（比如"家庭共享账本" + "个人私密账本"）每个账本对应一个独立的 Beancount 文件？
用户可以创建多个账本。每个账本对应一个Beancount文件。

前端技术栈：你对前端框架有偏好吗？（React / Vue / Svelte？）还是由我来推荐？
用React

认证方式：用户登录用什么方式？简单的用户名+密码？还是需要支持第三方登录（微信/Google）？
简单的用户名和密码就可以。

预算提醒方式：超支提醒是仅在网页端展示，还是需要推送通知（邮件/微信通知等）？
仅在网页端展示，暂时不需要推送通知。

可以。
