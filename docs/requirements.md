# Clover Book 需求文档

## 1. 项目概述

**项目名称**：Clover Book（家庭记账本）

**项目目标**：构建一个面向家庭场景的多人协作记账应用，支持多用户同时记账和查看，以 Beancount 文件作为会计数据的唯一真相源（Single Source of Truth），数据库仅作为只读缓存加速查询。

**核心设计原则**：
- Beancount 文件是唯一真相，所有写操作最终必须反映在 Beancount 文件中
- PostgreSQL 数据库仅为查询缓存，可随时从 Beancount 文件重建
- 所有持久化数据集中存储于单一文件夹，便于备份和迁移

## 2. 技术栈

| 层级 | 技术选型 |
|------|----------|
| 前端 | React + 响应式设计（适配桌面/平板/手机） |

| 会计核心 | Beancount（单文件/账本） |

## 3. 用户与权限

### 3.1 用户系统

- 支持多用户注册和登录
- 认证方式：用户名 + 密码
- 支持多用户同时在线编辑和查看同一账本

### 3.2 账本权限模型

| 角色 | 权限 |
|------|------|
| 账本所有者 | 创建/删除账本、管理分类、记账、查看、分享账本给其他用户 |
| 账本成员 | 管理分类、记账、查看（不可删除账本） |

### 3.3 操作审计

- 每笔交易记录创建者（哪个用户记录的）

---

## 4. 账本模型

### 4.1 多账本支持

- 一个用户可创建多个账本（如："家庭共享账本"、"个人账本"）
- 每个账本对应一个独立的 Beancount 文件
- 账本可分享给其他注册用户

### 4.2 账户类型

支持以下常见账户类型：

| 分类 | 账户类型 |
|------|----------|
| 资产 (Assets) | 银行储蓄卡、现金、支付宝、微信钱包、投资账户 |
| 负债 (Liabilities) | 信用卡、花呗、借入款项 |
| 收入 (Income) | 工资、奖金、投资收益、副业收入 |
| 支出 (Expenses) | 按分类体系组织（见第5节） |
| 权益 (Equity) | 初始余额 |

### 4.3 交易类型

| 交易类型 | 说明 |
|----------|------|
| 支出 | 从资产/负债账户到支出账户 |
| 收入 | 从收入账户到资产账户 |
| 转账 | 资产账户之间的互转 |
| 报销 | 支出后收回款项 |
| 借入 | 从他人借入资金 |
| 借出 | 借出资金给他人 |

### 4.4 单一币种

- 仅支持人民币（CNY），不支持多币种

---

## 5. 分类与标签

### 5.1 分类体系

- 采用 **两级分类**（一级分类 + 二级分类）
- 用户可自定义添加/编辑/删除分类
- 系统预设一套常用分类

### 5.2 预设分类（示例）

| 一级分类 | 二级分类 |
|----------|----------|
| 餐饮 | 早餐、午餐、晚餐、零食饮料、外卖 |
| 交通 | 公交地铁、打车、加油、停车费 |
| 购物 | 日用品、服饰、数码电子、家居 |
| 居住 | 房租/房贷、物业费、水电燃气、维修 |
| 医疗 | 门诊、药品、住院、保健 |
| 娱乐 | 电影/演出、游戏、旅行、运动健身 |
| 教育 | 培训课程、书籍、文具 |
| 人情 | 红包礼金、请客、礼物 |
| 金融 | 手续费、利息支出、保险 |
| 其他 | 未分类支出 |

### 5.3 自由标签

- 每笔交易可附加多个自由标签
- 标签可用于灵活筛选和统计（如 `#旅行2024`、`#装修`）

## 6. 周期性交易

### 6.1 功能说明

- 支持创建周期性交易模板
- 到期自动生成交易记录（或提醒用户确认）

### 6.2 使用场景

| 场景 | 周期 | 说明 |
|------|------|------|
| 房租 | 每月 | 固定金额，自动生成 |
| 房贷 | 每月 | 固定金额 |
| 工资 | 每月 | 固定收入 |
| 分期付款 | 每月 × N期 | 有总期数，到期自动结束 |

### 6.3 配置项

- 金额（固定/手动确认）
- 周期（每日/每周/每月/每年）
- 起止日期
- 自动执行 or 仅提醒

---

## 7. 预算管理

### 7.1 预算设定

- 支持按月设定总预算
- 支持按分类设定月度预算（如：餐饮 3000元/月）
- 预算周期：月度

### 7.2 超支提醒

- 仅在网页端展示提醒（不做推送通知）
- 提醒时机：
  - 已用达到预算 80% 时：黄色警告
  - 已用超过预算 100% 时：红色警告
- 首页/仪表盘展示当月预算使用情况

---

## 8. 报表与统计

### 8.1 核心报表

| 报表 | 说明 |
|------|------|
| 月度收支总览 | 当月总收入、总支出、结余 |
| 分类占比 | 饼图展示各分类支出占比 |
| 收支趋势 | 折线图展示近 N 月收入/支出变化 |
| 家庭成员对比 | 柱状图对比各成员消费 |
| 账户余额 | 各账户当前余额一览 |
| 资产负债表 | 总资产、总负债、净资产 |

### 8.2 筛选维度

- 时间范围（日/周/月/年/自定义）
- 分类筛选
- 标签筛选
- 账户筛选
- 成员筛选

## 9. 数据导入/导出

### 9.1 导入功能

**通用 CSV 模板导入**：

设计一套标准 CSV 格式，字段包括：

```
日期,类型,金额,一级分类,二级分类,账户,备注,标签
2024-01-15,支出,35.00,餐饮,午餐,支付宝,公司楼下,工作餐
2024-01-15,收入,15000.00,工资,,招商银行,1月工资,
```

**随手记适配器**：
- 支持随手记导出的 CSV/XLS 格式
- 自动映射随手记的分类到系统分类
- 导入前预览，用户可调整映射关系

### 9.2 导出功能

- 导出为 CSV
- 直接下载 Beancount 源文件

## 11. Beancount 集成

### 11.1 数据流

```
用户操作 → 后端API → 写入Beancount文件 → 同步更新PostgreSQL缓存
                                ↑
                          唯一真相源（Single Source of Truth）
```

### 11.2 文件组织

- 每个账本对应一个 Beancount 文件
- 文件存储路径：`<数据目录>/ledgers/<账本ID>/main.beancount`

### 11.3 缓存同步策略

- 写操作：先写 Beancount 文件，再更新数据库缓存
- 读操作：从 PostgreSQL 缓存读取（性能优先）
- 全量重建：支持从 Beancount 文件重新构建完整缓存（用于修复/迁移）

### 11.4 源文件编辑

- 提供 Web 端 Beancount 源文件编辑器（面向高级用户）
- 编辑后自动校验语法
- 校验通过后重新同步缓存

## 12. 部署架构

### 12.1 Docker 部署

```yaml
# docker-compose.yml 示意
services:
  clover-book:
    image: clover-book:latest
    ports:
      - "3000:3000"
    volumes:
      - ./clover-data:/data    # 唯一持久化目录
    depends_on:
      - postgres

  postgres:
    image: postgres:16
    volumes:
      - ./clover-data/pg:/var/lib/postgresql/data
```

### 12.2 持久化目录结构

```
clover-data/
├── config/              # 应用配置
│   └── app.yaml
├── ledgers/             # Beancount 文件
│   ├── <ledger-id-1>/
│   │   └── main.beancount
│   └── <ledger-id-2>/
│       └── main.beancount
├── attachments/         # 附件文件
│   └── <ledger-id>/
│       └── 2024/
│           └── 01/
│               └── <file-hash>.jpg
└── pg/                  # PostgreSQL 数据
```

### 12.3 可移植性保证

- 复制整个 `clover-data/` 文件夹到新环境
- 运行 `docker-compose up` 即可恢复完整状态
- 数据库缓存即使丢失也可从 Beancount 文件重建

## 13. 前端页面规划

### 13.1 页面列表

| 页面 | 说明 |
|------|------|
| 登录/注册 | 用户认证 |
| 首页/仪表盘 | 当月收支总览、预算进度、最近交易 |

| 统计报表 | 各类图表和报表 |
